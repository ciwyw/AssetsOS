# 存储、备份与设置页

对应源码：`AssetsOS/BackupSystem.swift`、`AssetsOS/SettingsScreen.swift`、`AssetsOS/Models.swift`（Schema）、`AssetsOS/RootView.swift`

## 主数据

- SwiftData 本地数据库是唯一主数据，App 内所有汇总都从当前状态读取
- UserDefaults 只存备份配置（目录 bookmark、最近成功时间、最近错误），**不存业务数据**
- 删除 App 会删除本地数据库；覆盖安装不会

### SwiftData Schema

当前运行在 `AssetsOSSchemaV2`（2.0.0）。V1 → V2 是 lightweight migration，V2 相比 V1 只在 `Account` 上新增了 `boundBankAccountID`、`shAAccountCode`、`szAAccountCode`。

新增模型或字段时通过新 schema 版本实施，不使用运行时猜测迁移。

**注意**：SwiftData schema 版本和 JSON 备份的 `schemaVersion` 是两套独立的版本号。

## JSON 备份

用户通过系统文件选择器授权一个目录（通常是 iCloud Drive），App 保存 security-scoped bookmark。序列化业务数据为 JSON，**不直接复制 SQLite / WAL / SHM 文件**。

顶层结构：

```json
{
  "schemaVersion": 2,
  "exportedAt": "<ISO8601 UTC>",
  "accounts": [ ... ],
  "assets": [ ... ]
}
```

- 金额序列化为十进制字符串（`en_US_POSIX`）
- 日期型业务字段用 `yyyy-MM-dd`
- 时间戳用 ISO 8601
- 输出为 pretty-printed + sortedKeys

Account 导出全部字段（含证券绑定三字段和 `closedAt`）；Asset 导出全部字段（含定期专属字段、来源 ID、结清信息）。

### 文件命名与保留

| 类型 | 文件名 |
|---|---|
| 最新备份 | `AssetsOS.json` |
| 当日历史 | `AssetsOS-yyyy-MM-dd.json` |
| 恢复前安全备份 | `AssetsOS-pre-restore-yyyyMMdd-HHmmss.json` |

每次成功写入会同时更新最新文件和当日历史文件。历史文件按日期降序**保留 3 份**，其余删除；`AssetsOS.json` 不参与清理；`pre-restore` 安全备份不自动清理。

同一天多次备份只覆盖同一个历史文件，不会每 5 分钟堆积一个新文件。

### 自动备份

- 监听 `ModelContext.didSave`，每次业务数据变化后标记需要备份
- **5 分钟节流**：距上次成功不足 5 分钟时等待补足，期间的多次修改合并为一次写入
- App 进入后台时，若还有待写入的任务则立即执行
- 自动备份失败**不阻止本地保存**

以下情况暂停自动写入：未配置目录、存在待处理的旧备份、已有备份任务在跑。

### 校验

只接受 `schemaVersion` 为 1 或 2。校验项：账户 ID 唯一、资产 ID 唯一、资产的 accountID 必须存在、`boundBankAccountID` 必须指向同一备份内类别为银行的账户、`sourceCashAssetID` 必须指向同一备份内的活期或活期+。

旧备份（`schemaVersion = 1`）缺少的证券字段按 `nil` 读入，没有额外迁移代码。未知的类别或类型 raw 值回退为"其他" / "活期"。

## 恢复备份

**整库替换，不做合并。**

流程：

1. 用户在设置页选择 `.json` 文件，或处理"目录中发现旧备份"
2. 先完整读取并校验；**校验失败不清空本地数据**
3. 展示预览：备份时间、账户数量、资产数量、定期数量、schemaVersion
4. 文案 `恢复采用整库替换，不做合并。恢复前会先校验备份并额外保存当前数据。`
5. 确认后：把当前数据额外导出为恢复前安全备份 → 取消全部已安排通知 → 删除现有全部资产和账户 → 导入备份数据 → 按恢复后的定期重排通知

安全备份的落点优先级：已配置的备份目录 → 源文件所在目录 → 系统临时目录。

失败时弹 Alert 显示错误信息。

## 首次使用与新安装

启动没有 onboarding，也不写入任何预置账户或样例资产。默认 Tab 是总览。

未配置备份时 App 可正常使用，总览显示"尚未配置备份"横幅，设置页提供选择目录入口。

**新安装发现已有备份**：卸载会带走 bookmark，所以新安装无法在未授权的情况下自动扫描 iCloud Drive。用户首次选择备份目录时，如果本地库为空且目录中存在可解析的 `AssetsOS.json`，则：

- 不立即覆盖旧备份
- 暂停向该目录自动写入
- 总览和设置页提示待处理
- 等用户明确选择：恢复该备份 / 用当前数据覆盖旧备份 / 选择新目录

本地已有数据，或目录中没有旧备份时，配置完直接写入一次。

## 设置页

从账户页右上角齿轮进入。

**备份区块**：

| 行 | 内容 |
|---|---|
| 状态 | 正常 / 未配置 / 失败 / 等待处理已有备份 |
| 备份目录 | 已配置时显示目录名 |
| 最近成功备份 | `yyyy-MM-dd HH:mm`，有记录才显示 |
| 立即备份 | 已配置且非等待状态时可用，执行中显示"备份中…" |
| 选择 / 更换 / 重新选择目录 | 文案随状态变化 |
| 恢复备份 | 打开 `.json` 文件选择器 |

**"目录中发现旧备份"区块**：仅在等待处理状态出现，含备份预览和三个操作（恢复该备份、用当前数据覆盖旧备份、选择新备份目录）。

**通知区块**：显示通知权限状态；定期提醒规则为固定文案 `到期前 3 天 / 当天 09:00`，**不可配置**。

设置页没有其它条目——没有主题、货币、关于、清空数据、外部导入。

## 安全边界

- 不做 App 层备份加密、不做 Face ID、不做后台金额遮罩
- 有权访问备份文件的人可以直接读取 JSON 内容
- 两台设备同时写同一目录可能互相覆盖
