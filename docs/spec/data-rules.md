# 数据规则与工程约束

对应源码：`AssetsOS/Support.swift`（Money、DateKit、AppTheme）、`AssetsOS/Models.swift`、`AssetsOS/Engine.swift`

## 技术栈

- SwiftUI + SwiftData，本地单机，无服务端
- 金额一律用 `Decimal`，**严禁 `Double`**
- 使用 `VersionedSchema` 和显式迁移计划

## 金额

统一 2 位小数。`Money.rounded` 默认 scale 为 2、模式为 `.plain`（半值远离零，即常规四舍五入）。展示走 `Money.string`，locale `zh_CN`，千分位 `,`，货币符号 `¥`。

年化利率入库存小数（6% 存 `0.06`），scale 为 6；界面输入和展示都用百分数。

金额不能小于零。

### 派生值不落库

以下全部实时计算，**不缓存、不落字段**：

- 账户金额
- 总资产 / 净资产
- 类别分布
- 资金状态分布
- 投资盈亏
- 定期预计利息
- 定期生命周期状态

唯一的"当前金额"统一入口是 `Asset.currentPortfolioAmount`：定期未结清取本金、已结清取 0，其余类型取 `currentAmount`。任何新增汇总都必须走这个属性，不要直接读 `currentAmount`。

### 汇总口径速查

```text
账户金额 = Σ 该账户当前资产的 currentPortfolioAmount
总资产   = Σ 全部当前资产的 currentPortfolioAmount
当前资产 = 全部资产 - 已结清定期
投资盈亏 = 当前市值 + 累计取回 - 累计投入   （基金/股票/银行理财）
         = 实际到账 - 本金                （已结清定期）
预计利息 = 本金 × 年化 × 全期天数 ÷ 365     （仅展示）
```

## 日期

`DateKit` 统一提供日历和格式化器：公历、locale `zh_CN`、周一为一周起始、时区 **`.autoupdatingCurrent`（设备本地时区）**。

- **业务日期**（起息日、到期日、解锁日）保存为设备本地时区当日 0 点，展示和备份都按本地时区解释。历史上曾因展示 formatter 固定 `GMT+0` 导致东八区显示早一天，已修复——新增日期展示必须走 `DateKit`，不要自建 formatter
- **时间戳**（createdAt、updatedAt、settledAt）保存完整时刻，备份序列化为 ISO 8601 UTC
- 展示格式：完整日期 `yyyy-MM-dd`，列表短日期 `MM-dd`，日期时间 `yyyy-MM-dd HH:mm`
- 相对到期文案：`已到期 N 天` / `今天到期` / `明天到期` / `N 天后到期`
- 天数差按两个日期的 0 点计算日历天数差

**状态边界**：到期日当天算"待结清"。锁定日晚于今天才算"锁定中"，等于今天即视为已解锁。

## 唯一性与校验

| 对象 | 唯一性范围 |
|---|---|
| 账户名称 | **全局唯一**（跨类别） |
| 资产名称 | **同账户内的当前资产唯一**（排除已结清定期），不同账户可同名 |

其它校验：

- 到期日必须严格晚于起息日
- "从现有资金"创建时，来源余额必须 ≥ 支出金额
- 转账金额必须 > 0

## 原子操作

以下动作必须在一次保存中完成，不允许出现中间态：

- 从现有资金创建定期：扣减来源活期 + 新建定期
- 从现有资金买入投资：扣减来源现金 + 新建投资
- 现金互转：一侧减、一侧加
- 定期结清：活期入账 + 写入结清字段 + 取消通知
- 定期删除（从现有资金创建的）：退回本金 + 删除记录 + 取消通知

## 删除关系

`Account.assets` 的 SwiftData 删除规则是 `.deny`，作为业务层阻断之外的第二道保护。账户下有任何资产记录时都无法删除账户。

## 预留字段

模型里存在但**当前业务代码完全不读写**的字段。不要基于它们产生任何行为：

| 字段 | 位置 | 状态 |
|---|---|---|
| `closedAt` | Account、Asset | 恒为空，只有备份序列化会读写它 |
| `balanceSide` | Asset | 恒为资产侧，汇总不读它 |
| `loanReceivable` / `loanPayable` | AssetKind | 无创建入口，详情页落到"暂不支持"分支 |
| `personalRelations` | AccountCategory | 不在类别选择器和账户页分组中 |

## 配色语义

`AppTheme.gain` 是红褐色，用于**正向盈亏和危险操作**；`AppTheme.loss` 是绿色，用于负向盈亏。这是中文市场的涨红跌绿习惯，与欧美相反——读代码时注意 `gain` 不等于"成功色"。
